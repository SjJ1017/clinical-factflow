# MedCaseReasoning：24 例全连接 pilot

已准备 **24 例 × 5 条件 = 120 场 trace 的输入与完整 YAML**；尚未调用模型生成、抽取或匹配。每场为 3 agents × 3 rounds；若执行且无重试，共 1,080 次生成调用。统计上的独立病例数仍是 24，不能把 120 个配对条件或 1,080 个 turn 当作独立样本。

直接打开 [英文病例分区查看页](../data/medcasereasoning/pilot24/review.html)。它包含全部入选题干、逐段原文分区、来源链接、逐例选入理由与局限，以及默认折叠的参考诊断和推理。参考内容不会进入 agent 输入。浏览器 URL 安全策略阻止了本次本地预览，页面尚未完成视觉验收；数据和配置离线校验已通过。

## 五个条件与可比较的效应

| 条件 | 初始证据 | 角色 |
|---|---|---|
| shared-generic | 每人全部证据 | 三个相同 generic 提示词，独立生成 |
| shared-specialist | 每人全部证据 | 临床评估／影像／检验与病理专家 |
| split-generic | 三个来源分区各给一人 | 三个相同 generic 提示词，独立生成 |
| split-specialist | 同一套分区，各给一人 | 专家与其来源匹配 |
| split-mismatched | 与 split-specialist 完全相同 | 三个专家角色全部错配 |

每个条件的模型、温度、输出上限、task prompt、轮数、记忆规则、抽取与匹配参数一致。specialist 指**来源相关的职能专业化**，不是心内科／神经科等器官科室；这与选定分区对应。所有角色均可解释收到的其他来源证据，不要求模型假装无法理解其他专业。

- 拓扑只有 full，采用同步轮次屏障。R1 三人互不可见；R2/R3 读取两位同伴上一轮输出。自己的历史全部保留，原始分区每轮可见。
- 六种“来源→A/B/C”排列各用于 4 例；同一病例的五个条件保持角色与座位约定一致。
- 错配只改变 role 与 prompt，不改来源分配。两种无固定点的三循环各用于 12 例，每种座位排列都包含两种错配方向。
- 120 份 YAML 都独立展开完整配置，无继承覆盖。run-matrix.json 另给出固定哈希打散的执行顺序，减少按条件连续执行与服务状态变化重合的风险；目前没有执行。
- 共享条件会重复发送更多输入文字，这是信息可见性处理本身的一部分。不要把“相同 max_tokens”写成相同实际 token 成本。

主要比较：在 shared/split 内分别比较 specialist−generic，估计角色效果是否随信息分布而变；在 generic/specialist 内比较 split−shared；用 split-mismatched 对照 split-specialist 检验匹配特异性，并同时对照 split-generic 判断错配是否比无专业角色更差。此规模用于发现大效应、检查失败机制和测量稳定性，不足以宣称小差异成立。

## 筛选过程与偏差

数据来自官方 [MedCaseReasoning](https://huggingface.co/datasets/zou-lab/MedCaseReasoning) 的 **train split**，固定 revision `469a536`。原始 parquet SHA-256：

```text
12b23b1d652caff931ea53012e8b84c2e74bfd3c6394c4fcdea63afa74158207
```

没有读取验证／测试集参与这次筛选。公开下载不需要 credentialing；本地整理不会再从文章全文补充证据。[论文](https://arxiv.org/abs/2505.11733)与数据卡应作为原始数据构建说明，不能把本文的来源分区或临床方向误写为作者提供的标注。数据卡标记 MIT；这不是对每篇原始文章独立版权的额外授权，本次没有公开发布原文集合。

1. **全量廉价筛查 13,092 行。** 题干 210–550 个空白分隔词、至少 4 个不同检验相关匹配词、2 处影像关键词、5 个数字匹配；去除完全相同题干、无参考条目，以及开头 260 字符出现动物关键词的条目。数字和关键词只是候选代理，不是真实事实计数。动物词规则保守，可能误排含动物接触史的人类病例；不声称是准确的物种分类器。550 上限没有实质截断作用，本版全体最大值仅 479 词。
2. **留下 1,481 个候选。** 按题干关键词给出六个粗略方向，方向内用 `SHA256(20260909:PMCID)` 固定排序。先审阅各方向前 20 例，后扩展 systemic 的 12 例和 abdominal 的 8 例，共 140 例。扩展和替换属于本次探索过程，不是假称预注册的抽样方案。
3. **逐例由助手审阅题干与参考标签。** 关注三类来源是否各有实质内容、跨源推断是否有意义、时间和阴性证据、参考答案是否过度具体、方向覆盖及重复疾病。最终保留 24 例，六个手动临床方向各 4 例。关键词方向仅用于找候选，入选后可能调整方向，例如 Charcot arthropathy 属于神经—肌骨整合病例。
4. **分区验收后替换四例。** 训练行 1427→2577、8515→760、5999→8918、5971→423。被替换的病例有一个分区过薄；替代者来自已审阅池。最终每个分区至少 30 词，但这只是避免近乎空的分区，不能证明三个分区同等重要。
5. **固定样本与变换。** 24 例 PMCID、原文校验和、手工跨度分类、理由与 caveat 均保存；之后五个条件使用完全相同病例。尚未根据任何单／多 agent 的对错筛掉病例，也未进行付费或外部模型筛选。

这是一组**有目的抽取的、证据较丰富的可行性病例**，不是随机临床人群样本，也不是严格标签盲选。较长题干、更多检查、病例报告和均衡方向配额都会引入选择偏差。避免“全是某病”不等于消除偏差。不要将最终准确率推广到全部 MedCaseReasoning 或真实就诊人群，也不要在运行后只保留某条件获胜的病例。

| 临床方向（手动宽泛分组） | 数量 |
|---|---:|
| 心血管 | 4 |
| 呼吸 | 4 |
| 神经／神经肌骨 | 4 |
| 腹部／消化 | 4 |
| 肾脏／内分泌／代谢 | 4 |
| 全身／免疫／肌骨 | 4 |

24 个不同 PMCID，报告男性 13 例、女性 11 例，儿童 5 例。机制粗分为炎症 9、肿瘤 4、感染 3、血管 2、遗传 2，其余血栓／创伤后／药物相关／神经病性各 1。**炎症仍占 37.5%**；这组病例没有被声称为病因均衡样本。机制是助手辅助分组，不是经过医生核验的疾病本体标注。

整合复杂度主观分为 moderate 12 例、higher 12 例，各方向各 2 例。该标签不是模型难度分数，也不是预先验证的困难子集。保留较直接的诊断线索作为参照，避免只有稀有疾病与证据不足病例。实际困难程度应在执行后报告，不能依据标签预先宣称。

## 文字分区与信息量

| 空白分隔词数 | 最小 | 中位 | 最大 |
|---|---:|---:|---:|
| 原始 train 题干 | 45 | 178 | 479 |
| 入选 24 例题干 | 216 | 274 | 355 |
| 临床病史、体征、床旁功能评估 | 71 | 133.5 | 199 |
| 影像报告 | 37 | 67 | 115 |
| 检验与病理 | 32 | 66 | 169 |

分区是连续原文跨度的归属，不是总结、改写或生成新报告。每个跨度有 `[start,end)` 字符位置；按原文顺序拼接可逐字重建 `case_prompt`，不引入完整文章、标题、参考推理里的额外检查结果。保留报告中已有的诊断意见、临床怀疑、数值、单位、时间、标本身份和阴性结论；不把它们都转成确定事实。

有 **26 个已标记混合来源句**。为保留时间和语义限定，它们整体归给主要来源，不复制到两个分区。例如“第十六天再次疼痛，肌酐与炎症指标变化”完整保留在检验分区。这意味着来源并非完全隔离：实验研究的是主导来源与职能角色匹配，不能声称每个 agent 的输入是纯粹的单一模态。ECG、EEG、肌电、肺功能等床旁／生理评估通常归 clinical；超声、PET、微血管可视化等归 imaging；内镜／操作与组织学混合句按主要信息及上下文手工归类并标记。

这些词数与 source unit 数量**不是原子事实数**。尚未进行 minimax 抽取和进一步原子化，因此还不能报告每例真正有多少事实、需要多少跨源事实联合才能作答。

## 参考答案与初步准确率

部分题干给出强诊断线索；另一些只支持较宽诊断，参考却要求亚型或具体病原。逐例 caveat 已写入查看页。例如急性胰腺炎比“出血性”亚型更有可见证据，胰腺肿瘤的腺泡细胞亚型在题干没有病理确证。**参考答案存在，不等于题干足以唯一推出它，也不等于有逐事实真假 gold。** 这也是不能用“难”遮蔽的问题。

本版保留 source reference 原文，`outcome.scoring: ungraded`。现有字符串 majority 只记录技术性聚合，可能把诊断同义词当不同答案；不能据此直接报告临床系统准确率。正式比较前应固定：角色／条件盲的语义诊断归一规则、对临床等价答案的接受范围、主诊断与亚型分级评分、信息不足条目的处理和三人最终意见的聚合规则。该规则应在查看各条件表现前冻结，对五个条件统一应用。

初步分析应以病例配对比较为单位，并保留全部病例的结果、平局／无法判定和故障状态。准确率、返回可靠性、token 成本与轮次应分别报告；不要将 timeout 当作临床推理错误。若未来扩样，另取冻结的新病例做验证，避免反复在这 24 例上修改角色再宣称泛化效果。

## 文件与重建

- `data/medcasereasoning/pilot24/review.html`：英文、内嵌数据的查看页。
- `cases.jsonl`：canonical 输入与独立 reference 字段，runner 不把 reference／metadata 送入提示词。
- `screening.jsonl`：全体 13,092 行廉价筛查审计，无全文。
- `review-ledger.jsonl`：140 例审阅池、入选状态与有限的决策记录；非入选不表示该病例不可用。
- `review.json`：24 例逐段跨度、手动理由、caveat、来源链接与私有参考。
- `manifest.json`：原始数据和配置校验和、样本构成。
- `run-matrix.json`：120 份配置及打散的建议执行顺序。
- `validation.json`：离线校验结果。
- `configs/pilots/medcase24/`：120 份完整 YAML，一份只对应一例、一个条件、一个 replicate。
- `scripts/medcase24/`：固定选择、跨度映射、离线构建与验证代码。原始病例、生成页面与审计数据全部位于已被 Git 忽略的 `data/`，没有复制旧项目的 trace／抽取／分析结果。

离线复核（在新项目根目录，已安装项目及 parquet 依赖）：

```bash
python scripts/medcase24/verify.py --root .
```

重建需要上述 checksum 对应的官方 train parquet，进入**新的临时输出目录**重建，避免覆盖已执行实验的定义：

```bash
python scripts/medcase24/build.py \
  --parquet /path/to/train-00000-of-00001.parquet \
  --base-config configs/medcasereasoning-pilot.yaml \
  --root /tmp/medcase24-rebuilt
```

构建脚本不下载、不调用模型、不执行任何 run。已有目标 YAML 时拒绝覆盖。固定的 selection.json 和 partitions.json 是本次人工审阅决策的复现输入，不是一个可自动泛化到新病例的专业分类器。只保留元数据和所选题干，未将 99 MB 的完整原始文章 parquet 复制入新项目；原始下载目前留在临时缓存，可按固定 URL 与 checksum 重新取得。
